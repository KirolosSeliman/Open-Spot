# Search Console and Webmaster Verification

Manual setup for Google Search Console and Bing Webmaster Tools on production.

## Vercel variables to add manually

Codex cannot generate these values. They must be copied from Google Search Console and Bing Webmaster Tools. Do not invent them.

```text
NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=<paste the content value generated by Google Search Console>
NEXT_PUBLIC_BING_SITE_VERIFICATION=<paste the content value generated by Bing Webmaster Tools>
```

Add both in **Vercel → Project → Settings → Environment Variables → Production**. Redeploy after any change.

## Google Search Console

1. Go to [Google Search Console](https://search.google.com/search-console).
2. Add a **Domain** property for `open-spot.ca`.
3. **Prefer DNS TXT verification** for domain-level ownership when your registrar allows it.
4. If using **HTML tag** verification instead:
   - Copy only the `content` attribute value from Google's meta tag.
   - Set `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` to that value in Vercel Production.
   - Redeploy.
   - Click **Verify** in Search Console.
5. Submit `https://open-spot.ca/sitemap.xml`.
6. Use URL Inspection on `https://open-spot.ca` and request indexing for key public pages (see [indexing-urls.txt](./indexing-urls.txt)).

## Bing Webmaster Tools

1. Go to [Bing Webmaster Tools](https://www.bing.com/webmasters).
2. Add `https://open-spot.ca`.
3. Import from Google Search Console if offered.
4. If using **HTML meta** verification:
   - Copy only the `content` value from the `msvalidate.01` tag.
   - Set `NEXT_PUBLIC_BING_SITE_VERIFICATION` in Vercel Production.
   - Redeploy.
   - Verify in Bing.
5. Submit `https://open-spot.ca/sitemap.xml`.

## Notes

- These variables are optional. DNS verification for Google does not require `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`.
- Meta tags render only when the corresponding variable is non-empty.
- Never commit real verification tokens to the repository.
